System design

Edge backup, zero plaintext secrets

Deploy credentials never touch git. Runtime credentials never touch disk. The Worker is a single V8 isolate that speaks Google Calendar and stores snapshots in KV.

Deploy path (JIT from Azure Key Vault)

Azure Key Vault · dp-kv-deliverypilot Secrets (names only): cloudflare-api-token, cloudflare-account-id, gcp-service-account-json
▼ npm run deploy:azure · in-memory env only
Wrangler on the operator laptop / CI 1. az keyvault secret show → process env
2. npm run build (file + anti-secret scan)
3. wrangler deploy HTML + Worker
4. stdin pipe → wrangler secret put GOOGLE_SERVICE_ACCOUNT_JSON
▼ TLS to Cloudflare API · no .env file written
Cloudflare account contact@rifaterdemsahin.com Worker pexabo-calendar-backup + KV binding BACKUPS + encrypted Worker secret

Runtime path (every request)

1
Browser or agent hits / (Push UI), /api/*, or POST /mcp on the nearest Cloudflare colo.
2
Worker isolate signs a Google JWT (RS256, WebCrypto) with the service-account private key held in the Worker secret store.
3
Google Calendar API calendars/info@pexabo.com/events — list, get, insert, patch, delete according to ACL.
4
Cloudflare KV BACKUPS stores snapshot JSON (backup:<id>) and a rolling index of the last 50 backups.

Why Workers, not a VM

  • Sub-5ms cold starts (V8 isolates, not containers).
  • Anycast: one URL, 300+ cities, no region pinning.
  • Free tier covers 100k req/day — this POC will not leave it.
  • HTML is bundled as text modules; one deploy ships UI + API.

Trust boundaries

  • Git / GitHub: source only. .gitignore blocks .env, .dev.vars, PEMs, SA JSON.
  • Azure KV: source of truth for deploy + Google credentials.
  • Cloudflare secret store: runtime copy of the SA JSON, never logged.
  • KV: calendar snapshots (event payloads), not credentials.
